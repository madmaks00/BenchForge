# Фактические проверки BenchForge

Дата: 16 ноября 2026. Основная машина: Windows x64, .NET SDK 10.0.302 / runtime 10.0.10, Docker Desktop с Linux-контейнерами.

Дополнение от 17 ноября 2026: серверный режим с управлением по SSH проверен отдельно; подробности ниже.

## Движки и базы

Реальные процессы C#, Java, Python, Rust, Node.js и Go проверены с PostgreSQL, MySQL, MariaDB, MongoDB, Redis, Valkey, ClickHouse и SQLite: **48 сочетаний движок × СУБД**. Выполнены все операции, которые поддерживает соответствующий профиль, включая первоначальную загрузку и создание индексов там, где они предусмотрены.

Получены **414 проверенных измерений без ошибок операций** по итогам прогонов и повторных проверок исправленных сочетаний. Размер набора — 100 записей, 2 клиента, 1 повтор, 0,1 с на операцию, пакет 20 записей, текстовое поле 16 байт. Это функциональные проверки, **не измерения для рейтинга языков или СУБД**.

Проверялись количество записей, сумма ID и сумма значений после загрузки, а также количество записей после каждого сценария. Неподдерживаемые операции не подменялись нулевыми результатами. После серверных прогонов принадлежащие им контейнеры удалены; образы оставлены.

Проверенные среды на Windows: JDK 21.0.10, CPython 3.14.3, Rust 1.100.0, Node.js 24.20.0, Go 1.27.4. Версии драйверов, серверов и параметры хранения сохраняются в реальных отчётах.

## Автоматические и сквозные проверки

- Release-сборка основного решения прошла без ошибок и предупреждений.
- **104 автоматических теста прошли.** Они покрывают генерацию данных, гистограммы, метрики, валидацию конфигурации, протокол, профили нагрузки, отмену, очистку, оценку результатов и независимость случаев, серверный режим и собственные SQL-сценарии.
- Для нескольких языков проверены выбор движков, совместимость старых конфигураций с C#, смена порядка между повторами, разные caseId и адреса временных SQLite-файлов, отклонение метаданных/результатов другого движка, разделение измерений по языку и БД, сохранение null для неизмеренного GC.
- Перед запуском нативные движки проходят сверку SplitMix64, трёх записей с разными seed, включая `ulong.MaxValue`, и гистограммы с эталоном C#.
- Каждый из шести движков выполнил собственный график: переход 1 → 2 → 3 → 1 клиент, смена заданной частоты и закрытого цикла, чтение, смешанная нагрузка, вставка и пакетная вставка. Получены **108 проверенных результатов**, включая подготовку. Проверены горячие ключи и максимальный 64-битный seed.
- Для каждого движка проверена перегрузка: 100 000 пакетных операций/с, 2 клиента, 0,2 с. Сохранены успешные операции и пропуски; выполнено равенство `planned = successful + errors + dropped = 20000`, а задержка с ожиданием не меньше service-задержки.
- Для всех шести движков проверена отмена через управляющий канал: частичный отчёт сохранён, временные SQLite-файлы удалены.
- Подготовка Windows-пакетов проверена штатным `workers/prepare.ps1`; повторная подготовка не дублирует записи в манифесте. Java пересобран после форматирования. Для Python подтверждено совпадение синтаксических деревьев до и после форматирования.

## Linux и чистые VM

Java, Python, Rust, Node.js и Go собраны штатным Linux-скриптом в Ubuntu 24.04 x64. Каждый из пяти новых движков выполнил **все операции SQLite в отдельной чистой VM**: **50 проверенных результатов, ноль ошибок**. У пяти гостевых систем разные ID загрузки ядра. Отчёты переданы на Windows и объединены координатором.

Ресурсы этого функционального прогона: 4 CPU, 1536 МБ RAM, диск 32 ГБ на VM. Память временно уменьшалась из-за доступных ресурсов основной машины. После проверки исходные настройки шаблона восстановлены: 4 CPU, 3072 МБ, 32 ГБ. Тестовые VM удалены, шаблон выключен, Docker Desktop возвращён в рабочее состояние.

Подготовка шаблона требует места для среды и образов. В Windows/Hyper-V при клонировании нужны временный экспорт и рабочая копия. В код добавлена проверка нижней оценки свободного места по занятому объёму гостевого диска, который сохраняется при подготовке нового формата шаблона. Физический VHDX может быть больше этой оценки.

## Интерфейс

Из основного проекта проверены шаги настройки, история отчётов, сравнение, графики нагрузки, подробные измерения, CPU/RAM и доли ошибок. В отчёте отображаются шесть отдельных серий; переключатель «Базы данных / Движки» фиксирует другую ось сравнения. Проверочное окно 1120 × 760 завершило обход с кодом 0, снимки интерфейса сохранены отдельно от приложения.

Исходники новых языков включены как файлы решения Visual Studio. Локальные пакеты `workers/dist` и скачанные зависимости исключены из Git. MIT проекта не меняет лицензии зависимостей.

## Серверный режим по SSH

Проверена настоящая передача исходников и сборка агента Docker из Windows через OpenSSH на отдельной Ubuntu 24.04 x64. В качестве сервера использовалась собственная временная VM: 4 CPU, 2048 МБ RAM, диск 32 ГБ. Это функциональная проверка серверного режима, а не испытание выделенного физического сервера или внешней сети.

- Агент с C# собран с нуля из SDK/runtime-образов .NET; затем отдельно подготовлен образ с C# и Python. На Windows серверные движки не выполнялись.
- C# проверен с SQLite и PostgreSQL: 8 измерений. Дополнительный прогон C# + Python с обеими БД: 16 измерений. Во всех 24 результатах проверка данных прошла, ошибок операций нет. Набор 100 записей, 1 клиент, 0,3 с на чтение/смешанную нагрузку, серверная БД ограничена 1 CPU/512 МБ. Такие числа не используются для рейтинга производительности.
- В отчёт получены серверные CPU, RAM, hostname, ОС, архитектура и ID образа агента; ОС и runtime Windows-контроллера записаны отдельно. Получены исходные выборки ресурсов и JSON/CSV. Короткие фазы могут не иметь серверной выборки RAM; отсутствие не подменяется нулём.
- Управляющая программа принудительно завершена во время PostgreSQL-прогона на 12 секунд. Повторный запуск `--resume-server` получил тот же ID задания и 3 измерения без повторного запуска теста. Пока сервер был занят, проверка нового запуска была отклонена.
- Прогон PostgreSQL на 30 секунд остановлен через запрос отмены: код завершения 2, частичный отчёт сохранён, временные контейнеры удалены.
- Проверен SSH с пробелом в пути `known_hosts`. Ключ сервера получен через доверенный канал к нашей тестовой VM; проверка ключа SSH не отключалась.
- Автоматически проверены повреждённый SHA-256, отчёт с другими настройками, попытка выхода файла архива за папку, отмена во время неоднозначного запуска, потеря связи/повторное подключение, отсутствие отчёта после ошибки агента, очистка и исключение локального пути приватного ключа из конфигурации отчёта.
- Интерфейс проверен в окне 1120 × 760: поля Linux-сервера, сохранение подключения, проверка настроек, библиотека и все три страницы отчёта. Сборка прошла без предупреждений.

Тестовая машина после проверок удаляется целиком. Исходный шаблон VM и его параметры не изменялись. Адреса, тестовый ключ и реальные отчёты проверки не входят в Git.

## Что пока не подтверждено

Дополнение о пользовательских SQL-сценариях приведено в следующем разделе.

- Реальный запуск на macOS, Apple Silicon и Linux ARM64. Скрипты подготовки для этих платформ добавлены, но устройств для проверки не было.
- Все серверные СУБД с каждым новым движком на Linux: полный набор серверных сочетаний проверен на Windows; Linux-проверка нагрузки новых движков охватывала SQLite.
- Предельная параллельность, десятки миллионов записей, суточные прогоны и калибровка частоты на выделенном оборудовании.
- Распределённая нагрузка с разных физических машин, репликация и восстановление после аварии. В добавленном SSH-режиме база и генератор находятся на одном сервере.
- Серверный режим на физическом Linux-сервере, Linux ARM64 и все сочетания шести движков с восемью СУБД через этот режим: его сквозная проверка охватывала C#/Python с SQLite/PostgreSQL в Ubuntu x64 VM.

Сравнивается реализация клиента: язык, runtime, драйвер и модель параллельности. Разные сборки SQLite, потоки, пулы, подготовка запросов и GIL могут влиять на результат. Короткие проверочные числа не включаются в приложение как демонстрационный рейтинг.

## Собственные SQL-сценарии — 17 ноября 2026

Сквозная проверка использовала Windows-контроллер и отдельный временный Linux-сервер Ubuntu 24.04 x64 в VM с 4 CPU, 2048 МБ RAM и диском 32 ГБ. База и C#-генератор находились на Linux; управление, передача файлов и получение отчётов выполнялись через настоящий OpenSSH.

- Интернет-магазин: четыре связанные таблицы, индексы, чтение карточки и JOIN-история, создание заказа из двух INSERT в транзакции, проверки отсутствия потерянных связей. Пройден с PostgreSQL, MySQL, MariaDB и SQLite.
- Кошельки: смесь чтения и транзакционных переводов с сохранением общей суммы. Пройден на тех же четырёх СУБД.
- Поля Int64, Text/Unicode, Decimal, Boolean, UTC-даты, Guid и NULL проверены на четырёх СУБД. Дополнительно на каждой проверен Sample-параметр из фактических UUID исходных данных.
- Собственный CSV с кириллицей, запятой и кавычкой внутри поля передан на Linux, загружен и прочитан на четырёх СУБД. Показан исходный размер импортированной таблицы, а не базовый объём.
- JSONL с произвольными строковыми первичными ключами проверен через Sample на четырёх СУБД. Исходный файл контроллера сохранил прежний SHA-256. Числовая последовательность ID для этого сценария не требовалась.
- Раздельное выполнение трёх операций магазина и смеси с графиком клиентов 1 → 2 → 1 проверено на SQLite и PostgreSQL через SSH: 24 измеренных интервала запросов, отдельная повторная загрузка данных перед каждой операцией/смесью, ноль ошибок.
- На Linux проверена отмена во время собственного сценария кошельков: статус cancelled, частичное измерение сохранено без добавления ошибок SQL. Намеренно неверный контрольный запрос `SELECT 1 = ожидаемое 0` дал статус partial, непроверенное измерение и диагностическое сообщение; успешным такой прогон не объявлен.
- В автоматических тестах проверены откат всей транзакции при неверном результате второго шага, передача Scalar следующему шагу, отмена с частичным отчётом, учёт заданной частоты, CSV с переносами/кавычками/разделителями, JSONL, контроль изменений файла, переносимый пакет, отказ от опасного пути архива и запрет перезаписи отличающегося входного файла при экспорте.
- Интерфейс действительно выполнил собственный сценарий: обойдены все пять страниц редактора и диалоги полей, SQL и проверок; описание после обхода не изменилось; сценарий магазина прошёл график 1 → 2 → 1; полученные измерения отображены в отчёте. Окно редактора 1060 × 790, основное окно 1120 × 760.

Серверным SQL-контейнерам для этих функциональных проверок задавались 1 CPU / 1024 МБ. Базовый объём 100, обычно 1 клиент, окна запросов 0,2 с; в графике — 0,1 с на интервал. Это проверки выполнения и целостности, не рейтинг производительности. Настоящий физический сервер, большие файлы, миллионы строк и длительные испытания этой функции отдельно не проверялись. Обмен файлами чистой VM подключён к существующему пути передачи, но отдельный новый сквозной прогон пользовательского импорта через режим чистой VM не выполнялся.

## Microsoft SQL Server — 17 ноября 2026

Проверен настоящий SQL Server 2025 (`17.0.5065.9`) из `mcr.microsoft.com/mssql/server:2025-latest`, Microsoft.Data.SqlClient 7.1.2, C# / .NET 10. Windows-контроллер управлял по OpenSSH временным Ubuntu 24.04 x64-сервером в VM: 4 CPU, 3072 МБ RAM, диск 32 ГБ. Контейнер базы: 2 CPU / 2048 МБ, внутренний лимит памяти 80% контейнера. Основной шаблон VM не изменялся.

- Все восемь стандартных операций, 1000 исходных строк, один и два клиента: 20 этапов с подготовкой, без ошибок, все проверки успешны. Пакеты по 1000 строк прошли через SqlBulkCopy; проверены количество записей и суммы, включая пакетную запись и удаление. В отчёте сохранены версия сервера, драйвер, image ID, SIMPLE / delayed durability DISABLED и настройки подключения.
- Магазин с JOIN и транзакционным заказом, кошельки с проверкой общей суммы, типизированный набор (UUID/Sample, UTC-даты, Decimal, Boolean, Unicode, NULL) и импорт CSV: по 10 корректных этапов на каждый сценарий при одном и двух клиентах.
- JSONL с произвольными текстовыми ключами и выборкой Sample: 5 корректных этапов; исходный файл не изменён.
- Магазин в сравнении SQL Server / PostgreSQL / SQLite с графиком 1 → 2 → 1: 21 этап, без ошибок, все проверки целостности успешны; полученные результаты открыты в UI.
- Намеренно ошибочный второй шаг транзакции: 50 отклонённых операций, общая сумма денег сохранилась. Ошибки отмечены в отчёте `completed_with_errors`.
- Отмена во время выполнения запросов: сохранены частичные данные, статус `cancelled`, отменённый результат исключается из корректных сравнений.
- Полная сборка без предупреждений; 108 автоматических тестов без пропусков. Открыты все страницы редактора, выполнен сценарий SQLite в UI, проверены выбор девятой базы, её значок и страницы реального SQL Server-отчёта при размере окна 1120 × 760.

Окна нагрузки 0,2 с, прогрев 0,1 с, один повтор: это функциональная проверка, не рейтинг производительности. SQL Server с Java, Python, Rust, Node.js и Go пока не реализован: UI и валидация запрещают такую комбинацию до запуска. ARM-образы SQL Server не поддерживаются. Отдельный полный прогон SQL Server через режим чистой VM и длительные испытания на физическом сервере не выполнялись; проверен серверный путь по SSH.
