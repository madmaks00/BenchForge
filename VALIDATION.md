# Фактические проверки прототипа

Дата: 16 ноября 2026. Машина проверки: Windows x64, .NET SDK 10.0.302 / runtime 10.0.10, Docker Engine 29.7.2 через Docker Desktop.

## Выполнено

- Release-сборка решения прошла без ошибок и предупреждений.
- **17 автоматических проверок прошли.** Проверены эталон SplitMix64, воспроизводимость данных, точность и объединение гистограмм, единицы метрик Docker, обработка управляющих символов вывода, пустые выборки, валидация настроек, возможности СУБД, сводные результаты, разделение ошибок и успехов, перегрузка планировщика, протокол, отмена и очистка.
- SQLite: отдельный worker-процесс выполнил все доступные сценарии с 1 и 2 клиентами; сквозной тест проверил **20 этапов**, контроль данных, JSON/CSV и удаление временного файла.
- **PostgreSQL, MySQL, MariaDB, MongoDB, Redis, Valkey и ClickHouse:** реальные изолированные контейнеры; по 1000 исходных записей, 2 клиента, по 0.3 секунды на сценарий, 1 повтор. Все **59 этапов** этих семи вариантов прошли проверку, ошибок операций не было. Это функциональные прогоны, не основание для рейтинга производительности.
- PostgreSQL после исправления чтения метрик: режим заданной частоты 500 операций/сек., 2 клиента, чтение и пакетная вставка по 3 секунды. Получены реальные выборки CPU/RAM/блочного ввода-вывода; ошибок сбора и операций не было. Проверено равенство planned = successful + errors + dropped. Пропуски при пакетной записи попали в отчёт.
- Avalonia: окно выполнило реальный тест SQLite, отобразило 10 этапов и график, сохранило отчёт. Автоматическая проверка окна завершилась с кодом 0; сохранён снимок реального интерфейса.
- После серверных прогонов созданные ими контейнеры удалены. Образы сохранены для повторного использования.

## Не подтверждено этими проверками

- Запуск на реальных macOS/Linux и Apple Silicon: исходники используют переносимые .NET/Avalonia API, но проверки выполнены на Windows x64.
- Предельная нагрузка, миллионы/десятки миллионов записей, длительные прогоны и устойчивость на протяжении суток.
- Точность расписания на разных ОС и при предельных частотах: видны опоздания/пропуски, но специальная калибровка на выделенном оборудовании ещё нужна.
- Удалённая или распределённая генерация, репликация и сценарии восстановления после аварии.
- Другие языковые движки: реализован только C#; общий протокол и точки подключения подготовлены.

Исходные проверочные отчёты не включаются в приложение как демонстрационные результаты. Новый пользователь видит собственные реальные измерения после запуска.
