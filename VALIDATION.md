# Фактические проверки BenchForge

Дата: 16 ноября 2026. Основная машина: Windows x64, .NET SDK 10.0.302 / runtime 10.0.10, Docker Desktop с Linux-контейнерами.

## Движки и базы

Реальные процессы C#, Java, Python, Rust, Node.js и Go проверены с PostgreSQL, MySQL, MariaDB, MongoDB, Redis, Valkey, ClickHouse и SQLite: **48 сочетаний движок × СУБД**. Выполнены все операции, которые поддерживает соответствующий профиль, включая первоначальную загрузку и создание индексов там, где они предусмотрены.

Получены **414 проверенных измерений без ошибок операций** по итогам прогонов и повторных проверок исправленных сочетаний. Размер набора — 100 записей, 2 клиента, 1 повтор, 0,1 с на операцию, пакет 20 записей, текстовое поле 16 байт. Это функциональные проверки, **не измерения для рейтинга языков или СУБД**.

Проверялись количество записей, сумма ID и сумма значений после загрузки, а также количество записей после каждого сценария. Неподдерживаемые операции не подменялись нулевыми результатами. После серверных прогонов принадлежащие им контейнеры удалены; образы оставлены.

Проверенные среды на Windows: JDK 21.0.10, CPython 3.14.3, Rust 1.100.0, Node.js 24.20.0, Go 1.27.4. Версии драйверов, серверов и параметры хранения сохраняются в реальных отчётах.

## Автоматические и сквозные проверки

- Release-сборка основного решения прошла без ошибок и предупреждений.
- **70 автоматических тестов прошли.** Они покрывают генерацию данных, гистограммы, метрики, валидацию конфигурации, протокол, профили нагрузки, отмену, очистку, оценку результатов и независимость случаев.
- Для нескольких языков проверены выбор движков, совместимость старых конфигураций с C#, смена порядка между повторами, разные caseId и адреса временных SQLite-файлов, отклонение метаданных/результатов другого движка, разделение измерений по языку и БД, сохранение null для неизмеренного GC.
- Перед запуском нативные движки проходят сверку SplitMix64, трёх записей с разными seed, включая `ulong.MaxValue`, и гистограммы с эталоном C#.
- Каждый из шести движков выполнил собственный график: переход 1 → 2 → 3 → 1 клиент, смена заданной частоты и закрытого цикла, чтение, смешанная нагрузка, вставка и пакетная вставка. Получены **108 проверенных результатов**, включая подготовку. Проверены горячие ключи и максимальный 64-битный seed.
- Для каждого движка проверена перегрузка: 100 000 пакетных операций/с, 2 клиента, 0,2 с. Сохранены успешные операции и пропуски; выполнено равенство `planned = successful + errors + dropped = 20000`, а задержка с ожиданием не меньше service-задержки.
- Для всех шести движков проверена отмена через управляющий канал: частичный отчёт сохранён, временные SQLite-файлы удалены.
- Подготовка Windows-пакетов проверена штатным `workers/prepare.ps1`; повторная подготовка не дублирует записи в манифесте. Java пересобран после форматирования. Для Python подтверждено совпадение синтаксических деревьев до и после форматирования.

## Linux и чистые VM

Java, Python, Rust, Node.js и Go собраны штатным Linux-скриптом в Ubuntu 24.04 x64. Каждый из пяти новых движков выполнил **все операции SQLite в отдельной чистой VM**: **50 проверенных результатов, ноль ошибок**. У пяти гостевых систем разные ID загрузки ядра. Отчёты переданы на Windows и объединены координатором.

Ресурсы этого функционального прогона: 4 CPU, 1536 МБ RAM, диск 32 ГБ на VM. Память временно уменьшалась из-за доступных ресурсов основной машины. После проверки исходные настройки шаблона восстановлены: 4 CPU, 3072 МБ, 32 ГБ. Тестовые VM удалены, шаблон выключен, Docker Desktop возвращён в рабочее состояние.

Подготовка шаблона требует места для среды и образов. В Windows/Hyper-V при клонировании нужны временный экспорт и рабочая копия. В код добавлена проверка нижней оценки свободного места по занятому объёму гостевого диска, который сохраняется при подготовке нового формата шаблона. Физический VHDX может быть больше этой оценки.

## Интерфейс

Из основного проекта проверены шаги настройки, история отчётов, сравнение, графики нагрузки, подробные измерения, CPU/RAM и доли ошибок. В отчёте отображаются шесть отдельных серий; переключатель «Базы данных / Движки» фиксирует другую ось сравнения. Проверочное окно 1120 × 760 завершило обход с кодом 0, снимки интерфейса сохранены отдельно от приложения.

Исходники новых языков включены как файлы решения Visual Studio. Локальные пакеты `workers/dist` и скачанные зависимости исключены из Git. MIT проекта не меняет лицензии зависимостей.

## Что пока не подтверждено

- Реальный запуск на macOS, Apple Silicon и Linux ARM64. Скрипты подготовки для этих платформ добавлены, но устройств для проверки не было.
- Все серверные СУБД с каждым новым движком на Linux: полный набор серверных сочетаний проверен на Windows; Linux-проверка нагрузки новых движков охватывала SQLite.
- Предельная параллельность, десятки миллионов записей, суточные прогоны и калибровка частоты на выделенном оборудовании.
- Удалённая/распределённая нагрузка, репликация и восстановление после аварии.

Сравнивается реализация клиента: язык, runtime, драйвер и модель параллельности. Разные сборки SQLite, потоки, пулы, подготовка запросов и GIL могут влиять на результат. Короткие проверочные числа не включаются в приложение как демонстрационный рейтинг.
