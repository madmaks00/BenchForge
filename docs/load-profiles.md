# Настройка нагрузки

Откройте **Новый эксперимент → Нагрузка**. Готовые режимы задают расписание запусков операций. BenchForge применяет весь план отдельно к каждой выбранной операции, размеру набора, повтору и базе. Подготовка данных, прогрев, ожидание завершения запросов и проверка данных могут увеличить общее время.

| Режим | Что происходит | Параметры |
| --- | --- | --- |
| **Быстрая проверка** | Короткий прогон для проверки подключения, подготовки данных и выполнения запроса | **Клиентов** — сколько одновременно работают. **Секунд** — время замера на операцию. По умолчанию 1 клиент и 2 секунды |
| **Постоянная нагрузка** | Число клиентов одинаково на протяжении замера. Каждый начинает следующую операцию после ответа | **Клиентов** — постоянная параллельность. **Секунд** — время замера. По умолчанию 8 клиентов и 30 секунд |
| **Рост нагрузки** | Движок повышает число клиентов по равным ступеням и отдельно измеряет каждую | **На старте** и **на последней ступени** — первый и последний уровни. **Ступеней** — число уровней включая оба края, от 2 до 12. **Секунд на ступень** — продолжительность каждого уровня |
| **Пиковая нагрузка** | Обычная нагрузка, резкий скачок, возврат к обычной. В отчёте три замера | **Обычная нагрузка** — число клиентов до и после пика. **Пик** — повышенное число клиентов. **До пика**, **Пик** и **Восстановление** — продолжительности трёх периодов |
| **Длительный тест** | Одинаковое число клиентов в нескольких интервалах, чтобы проследить за скоростью, задержкой и памятью | **Клиентов** — постоянная параллельность. **Минут всего** — суммарное время на операцию. **Интервалов измерения** — на сколько равных частей разбить время, от 2 до 24 |
| **Заданная частота** | Операции запланированы на старт с заданной частотой. Отчёт показывает выполненные, ошибочные и пропущенные операции | **Операций в секунду** — цель для всего этапа. **Параллельных клиентов, максимум** — предел одновременной работы. **Секунд** — время подачи нагрузки |

## Свой график

Нажмите **Свой график**. По горизонтали отложено время с начала замера, по вертикали — число клиентов. Щёлкните по свободному месту, чтобы добавить точку, или нажмите **+ Точка**, чтобы поставить её после последней. Перетаскивание меняет время и число клиентов. Можно выбрать точку в выпадающем списке и отредактировать её с клавиатуры.

| Поле | Что задаёт |
| --- | --- |
| **Время точки, с** | Абсолютное время. Стартовая точка закреплена на `0`, остальные идут по порядку |
| **Клиентов** | Параллельность в этой точке, от 1 до 2048 |
| **Цель, оп./с** | Частота старта операций в сумме по всем клиентам. При `0` они начинают новую операцию сразу после ответа. Если частота задана на обоих концах плавного отрезка, она меняется по той же кривой. Между режимами с целью и без цели переключение происходит в следующей точке |
| **Переход к следующей точке** | Форма от выбранной точки к следующей по времени |
| **Ступеней перехода** | Сколько равных по длительности этапов выделить на кривую. Значение на этапе берётся с начала его интервала. Больше ступеней — точнее приближение и больше границ между этапами |
| **Удержание в конце, с** | Сколько времени выполнять нагрузку последней точки |

**Удержание и скачок** сохраняет нагрузку до следующей точки, затем меняет её одним шагом. **Линейная** меняет нагрузку равномерно. **С разгоном** начинает медленно и ускоряется, **С замедлением** начинает резко и замедляется, **Плавный переход** постепенно разгоняется и замедляется к концу. Эти формы применяются и при росте, и при снижении нагрузки.

Для пика с 32 клиентами на 5 секунд задайте точки `0 с → 4`, `10 с → 32`, `15 с → 4`, выберите удержание на первых двух и поставьте 15 секунд удержания в конце. Для постепенного роста задайте `0 с → 4` и `30 с → 32`, выберите линейный переход на первой точке и укажите 6 ступеней.

Пунктир показывает заданную кривую, сплошная линия — расписание клиентов, которое выполнит движок. Этап, или интервал нагрузки, — отрезок времени с постоянным числом клиентов и постоянной целевой частотой. Например, переход с 4 до 32 клиентов за 10 ступеней создаёт 10 интервалов, затем начинается следующий отрезок графика. Число точек и общее число интервалов в пользовательском графике могут превышать 24. Один интервал длится от 0,05 до 3600 секунд. Если деление делает интервалы короче 0,05 с, уменьшите число ступеней или увеличьте время перехода. Между интервалами движок завершает операции и проверяет состояние набора. Настройки графика и рассчитанные интервалы сохраняются в JSON.

## Общие параметры

| Параметр | Что меняет |
| --- | --- |
| **Операции** | По умолчанию чтение по ID, а где оно недоступно — чтение диапазона. Можно выбрать конкретную операцию или все доступные для базы. Смешанный сценарий совмещает чтения и обновления в пропорции примерно 80/20 |
| **Записей в наборе** | Размер исходной базы. Несколько чисел через запятую задают отдельные наборы, от 100 до 100 млн записей каждый |
| **Повторов** | Сколько раз заново выполнить тест с теми же настройками, от 1 до 20 |
| **Размер текстового поля, байт** | Размер текстовой части каждой синтетической записи, от 16 до 65 536 байт |
| **Записей в пакете** | Число записей на пакет при загрузке и пакетной вставке. BenchForge может уменьшить его при больших полях, чтобы ограничить расход памяти на генерацию пакета |
| **Прогрев, секунд** | Дополнительное чтение до замеров. `0` отключает прогрев |
| **Начальное значение генератора** | Неотрицательное целое для воспроизводимости исходных данных и последовательностей ключей |
| **Лимит CPU базы** | Сколько процессорных ресурсов может использовать контейнер базы. Например, `2` соответствует вычислительному времени двух логических процессоров |
| **Лимит памяти базы, МБ** | Лимит оперативной памяти контейнера. SQLite работает в процессе генератора и использует ресурсы хоста |
| **Чаще обращаться к популярным ключам** | Чаще выбирает ключи из небольшой части данных, чтобы приблизить тест к нагрузке с популярными записями |
