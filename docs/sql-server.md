# SQL Server

**Microsoft SQL Server** поддерживает стандартные OLTP-тесты на всех шести движках. Через C# доступны собственные таблицы, импорт CSV/JSONL, SQL-запросы, транзакции и проверки целостности.

## Запуск

1. Выберите **SQL Server** на странице баз и нужные языки в разделе **Движки нагрузки**.
2. Настройте нагрузку. Для контейнера SQL Server требуется **не менее 2048 МБ RAM**. Для чистой VM нужно дополнительно хотя бы 1024 МБ для системы и генератора; для серьёзной нагрузки выделяйте больше.
3. Выберите окружение: локальный Docker, чистая VM или Linux-сервер по SSH. Для SQL Server нужен **Linux x64**. На Mac с Apple Silicon используйте сервер x64 по SSH: Microsoft не поддерживает ARM-эмуляцию своего образа.
4. Запустите эксперимент. На каждый прогон создаются отдельный контейнер и база `dblab`; после завершения контейнер удаляется. Существующие пользовательские базы не подключаются.

Готовый пример: `configs/sql-server-smoke.json`. Из корня проекта:

```powershell
dotnet run --project src/BenchForge.Cli -c Release -- --config configs/sql-server-smoke.json
```

Собственный сценарий магазина:

```powershell
dotnet run --project src/BenchForge.Cli -c Release -- --config configs/sql-server-smoke.json --workload configs/workloads/store.json
```

Текущий стандартный образ: `mcr.microsoft.com/mssql/server:2025-latest`. При необходимости закрепите конкретный тег/дайджест через `imageOverrides.sqlServer`. Отчёт сохраняет фактическую версию сервера и ID образа; тег `latest` может измениться.

## Запросы и данные

Стандартные тесты охватывают чтение по ключу, диапазон до 100 строк, агрегацию, обновление, смесь чтения и записи 80/20, одиночную и пакетную вставку и удаление. C# записывает пакеты через **SqlBulkCopy** с проверкой ограничений. Java, Python, Rust, Node.js и Go вставляют строки параметризованными командами в одной транзакции на пакет. Отчёт фиксирует этот способ записи.

Для своих сценариев загрузчик использует одинаковый подход для SQL-баз: подготовленный INSERT каждой строки внутри пакетной транзакции. Схема по умолчанию использует BIGINT/INTEGER, DECIMAL(28,12), FLOAT, BIT, DATETIME2(6), UNIQUEIDENTIFIER и NVARCHAR; текстовые ключи и UNIQUE имеют NVARCHAR(450), остальные текстовые поля — NVARCHAR(MAX). Длинный ключ требует своей схемы.

SQL Server использует свой диалект: например, `SELECT TOP (50) ...` вместо `LIMIT 50`. В редакторе SQL есть вариант **SQL Server**, в JSON — `overrides.sqlServer`. Автоматического переписывания пользовательского SQL нет. В шаблоне магазина вариант уже задан.

Сравнивая SQL-диалекты, проверяйте также NULL/UNIQUE, сортировки, блокировки и уровни изоляции: их поведение может отличаться. Число операций смеси считает целые бизнес-операции, включая все SQL-шаги и COMMIT.

## Условия измерений

Pooling выключен; каждому клиенту выделяется отдельное соединение. В стандартном профиле SQL Server используется восстановление SIMPLE и отключена отложенная фиксация: COMMIT остаётся долговечным, а журнал может повторно использовать освобождённое место. Это тестовый профиль, а не обещание совпадения с настройками продакшена. В стандартном отчёте записываются recovery model, delayed durability и режим Read Committed Snapshot.

Контейнер ограничивается общими настройками CPU/RAM. Внутренний предел памяти SQL Server задан как 80% RAM контейнера; остальное оставлено служебным структурам. Максимум ресурсов берётся по выборкам Docker, отдельно от памяти генератора.

Образ запускается в редакции **Developer**, предназначенной для разработки и тестирования, с `ACCEPT_EULA=Y`. Запуск принимает [EULA и условия образа Microsoft](https://learn.microsoft.com/en-us/sql/linux/quickstart-install-connect-docker?view=sql-server-ver17). BenchForge имеет лицензию MIT; лицензии сторонних СУБД действуют отдельно.

Используется [официальный Microsoft.Data.SqlClient](https://www.nuget.org/packages/Microsoft.Data.SqlClient/7.1.2). Пароль генерируется на каждый контейнер и передаётся через окружение Docker и закрытый канал движка. Порт доступен только на loopback тестового хоста. В локальном тестовом подключении шифрование необязательно, самоподписанный сертификат разрешён; через Интернет передаются команды и отчёты по SSH, а не порт SQL Server.
