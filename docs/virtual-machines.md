# Чистая виртуальная машина для каждого прогона

Откройте **Новый эксперимент → Нагрузка → Окружение тестирования** и выберите **Чистая виртуальная машина**.

BenchForge использует Multipass версии 1.15 или новее. Сервис устанавливается отдельно и выбирает подходящие средства виртуализации с учётом ОС. [Установка Multipass](https://canonical.com/multipass/docs/latest/how-to-guides/install-multipass/).

## Подготовка

Задайте имя шаблона, CPU, память и размер диска, затем нажмите **Подготовить шаблон**. Впервые потребуются интернет и свободное место для Ubuntu, Docker, .NET 10, пяти дополнительных языковых движков и образов выбранных баз. Кнопка в приложении подготавливает образы всех поддерживаемых серверных баз. Существующий принадлежащий BenchForge выключенный шаблон с такими же ресурсами обновляется этой же кнопкой. После добавления языков подготовку нужно повторить один раз.

Шаблон создаётся из Ubuntu 24.04 с часовым поясом UTC. После установки компонентов и загрузки образов машина выключается. Данные о ресурсах шаблона сохраняются локально, чтобы следующие прогоны использовали одинаковые настройки. Существующая машина с таким именем и другими настройками вызывает сообщение о необходимости выбрать другое имя.

Для размещения виртуальных дисков на другом диске выполните настройку хранилища самого Multipass до создания шаблона. [Инструкция Canonical](https://canonical.com/multipass/docs/latest/how-to-guides/customise-multipass/configure-where-multipass-stores-external-data/).

В Windows/Hyper-V клонирование требует места для временного экспорта и рабочей копии. После обновления шаблона BenchForge сохраняет занятый объём гостевого диска и проверяет нижнюю оценку свободного места: два таких объёма плюс 1 ГБ запаса. Фактический VHDX может занимать больше, поэтому эта оценка не гарантирует достаточную вместимость. При нехватке места обычный запуск с отдельными процессами и контейнерами остаётся доступен.

## Выполнение

Для каждой комбинации **движка, базы, объёма данных, числа клиентов и повтора** создаётся новая копия выключенного шаблона. BenchForge ждёт завершения начальной настройки гостевой ОС, затем внутри копии запускаются база, генератор нагрузки и сбор метрик. SQLite также выполняется внутри этой VM.

План нагрузки, операции, прогрев и проверки данных выполняются выбранным движком на C#, Java, Python, Rust, Node.js или Go. Запуски проходят последовательно. Подготовка компиляторов и зависимостей выполняется в шаблоне до эксперимента, а не в измеряемом окне. После прогона отчёт и исходные выборки ресурсов передаются на основной компьютер. Перед чтением архива проверяется его контрольная сумма SHA-256. Результаты всех копий объединяются в привычные `report.json`, `summary.json` и `results.csv`.

VM с именем вида `benchforge-case-<id>` выключается и удаляется после получения отчёта. Ошибка удаления останавливает эксперимент. При отмене BenchForge просит гостевой процесс сохранить частичный отчёт, забирает доступные результаты и удаляет машину.

В отчёте сохраняются ОС гостя, ОС основного компьютера, имя шаблона, имя конкретной VM, уникальный ID загрузки гостевого ядра и ресурсы машины. Общими остаются физическое оборудование и кэши основного компьютера. Внутри одного прогона операции и интервалы графика используют одну базу.

## Командный запуск

```sh
dotnet run --project src/BenchForge.Cli -c Release -- --prepare-vm --config configs/clean-vm.json
dotnet run --project src/BenchForge.Cli -c Release -- --check --config configs/clean-vm.json
dotnet run --project src/BenchForge.Cli -c Release -- --config configs/clean-vm.json
```

Подготовку шаблона достаточно выполнить один раз для выбранных ресурсов и образов баз. Готовый шаблон должен оставаться выключенным. Параметры `virtualMachine` сохраняются в настройках эксперимента и отчёте. Конфигурации без этих параметров запускаются на основном компьютере.
