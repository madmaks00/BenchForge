# Движки нагрузки

Каждая папка содержит самостоятельный процесс на своём языке. Он генерирует данные, вызывает драйвер БД, создаёт параллельную нагрузку, считает гистограммы и отправляет измерения координатору. Вызовов C# для выполнения нагрузки в этих движках нет.

| ID | Исходники | Выполнение |
| --- | --- | --- |
| `csharp` | `../src/BenchForge.Worker.CSharp` | .NET 10, асинхронные задачи |
| `java` | `java/src/main/java/dev/benchforge` | Java 21+, виртуальные потоки, JDBC и нативные клиенты |
| `python` | `python` | CPython 3.12+, отдельный поток и подключение на клиента |
| `rust` | `rust/src` | Rust 1.100+, отдельный системный поток на клиента |
| `node` | `node` | Node.js 24.20+, `worker_threads`, встроенный `node:sqlite` |
| `go` | `go` | Go 1.27.4+, goroutine на клиента, `modernc.org/sqlite` без CGO |

Все шесть движков поддерживают 14 БД в стандартных тестах. Профиль каждой БД определяет доступные операции. Например, полнотекстовый поиск доступен для Elasticsearch и OpenSearch, а аналитическое сканирование для ClickHouse и DuckDB. Поддерживаются заданная частота, прогрев, повторы, горячие ключи, этапы собственного графика и остановка с частичным отчётом. Свои SQL-сценарии запускаются на всех шести движках через их собственные драйверы.

| Движок | SQL Server | DuckDB | Oracle | CockroachDB |
| --- | --- | --- | --- | --- |
| C# | Microsoft.Data.SqlClient | DuckDB.NET | ODP.NET | Npgsql |
| Java | Microsoft JDBC | DuckDB JDBC | Oracle JDBC Thin | PostgreSQL JDBC |
| Python | python-tds | duckdb | python-oracledb Thin | psycopg |
| Rust | Tiberius | DuckDB C API | rust-oracle / Oracle Instant Client | postgres |
| Node.js | node-mssql / Tedious | DuckDB C API через Koffi | node-oracledb Thin | node-postgres |
| Go | go-mssqldb | DuckDB C API через purego | go-ora | pgx |

Для Elasticsearch и OpenSearch каждый движок выполняет HTTP-запросы своим клиентом. Встроенный DuckDB работает в процессе движка, поэтому его память входит в память процесса.

Для всех движков временный Oracle-контейнер получает 28-символьный пароль со 144 случайными битами. Эта длина совместима с ограничением входа в go-ora 2.9.0. [Описание ошибки драйвера](https://github.com/sijms/go-ora/issues/774).

## Подготовка на Windows

Установите нужные среды: JDK 21 и Maven 3.9+, Python, Rust с C++ Build Tools, Node.js, Go. C# работает после обычной сборки решения. Подготовка остальных движков скачивает зависимости и выполняется **до теста**.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File workers/prepare.ps1
# Или только выбранные языки:
powershell -NoProfile -ExecutionPolicy Bypass -File workers/prepare.ps1 -Engines java,go
dotnet build BenchForge.slnx -c Release
```

В интерфейсе: **Нагрузка → Движки нагрузки → Подготовить выбранные движки**. Здесь же можно проверить готовность. C# остаётся выбранным по умолчанию.

Скрипт ищет инструменты в PATH и в переносимом каталоге: параметр `-ToolsDirectory`, переменная `BENCHFORGE_TOOLCHAIN_HOME` или `%LOCALAPPDATA%/BenchForge/toolchains.json` с полем `directory`. Сам он не меняет системный PATH. Java, Node.js и Python должны быть доступны приложению через PATH. Для `prepare.ps1` переносимый Maven ожидается в `apache-maven-3.9.11/bin`, Go в `go/bin`, Rust в `cargo/bin` и `rustup`.

## Linux / macOS

После установки соответствующих JDK/Maven, Python/pip, Node.js, Go, Rust и инструментов C/C++:

```sh
bash workers/prepare.sh java,python,rust,node,go
dotnet build BenchForge.slnx -c Release
```

Скрипт определяет ОС и архитектуру. Для Python нужны готовые колёса зависимостей под выбранную версию и архитектуру. Движки Node.js, Go и Rust загружают официальную библиотеку DuckDB на этапе подготовки. Для Rust скрипт также скачивает Oracle Instant Client на Windows x64, Linux x64/ARM64 и macOS ARM64. На других поддерживаемых Oracle платформах установите Instant Client отдельно. В Ubuntu для Rust нужны `libaio` и `libnsl`, которые добавляет `install-linux.sh`. Библиотеки загружаются с путями отдельного процесса, системные переменные менять не требуется.

Для режима чистой VM нажмите **«Подготовить шаблон»** в настройках окружения. Подготовка обновит принадлежащий BenchForge выключенный шаблон, установит Linux-движки и снова выключит его. Это может занять заметное время и требует свободного места. Запуск тестов и создание копий начинаются после подготовки.

## Как устроены сборки

Готовые файлы находятся в `dist/<ОС>-<архитектура>/`; `engines.json` задаёт команду запуска. Это локальные результаты сборки, они исключены из Git. Исходники, `Cargo.lock`, `go.sum`, `package-lock.json`, версии Maven и `requirements.lock.txt` хранятся в репозитории. Пакетные зависимости сохраняют собственные лицензии; MIT проекта не меняет их лицензирование.

Подготовка заменяет пакет языка только после успешной сборки и самопроверки. `--self-test` выводит контрольные векторы SplitMix64, три записи, включая seed `ulong.MaxValue`, и гистограмму `binary128-us-v1`. Перед экспериментом координатор сравнивает их с эталоном C#. Пароли передаются через stdin, не через аргументы процесса и не в отчёт.

```sh
dotnet run --project src/BenchForge.Cli -c Release -- --prepare-workers --languages java,python,rust,node,go
dotnet run --project src/BenchForge.Cli -c Release -- --config configs/multi-engine-smoke.json
```

## Как понимать сравнение

В отчёте выберите **«Сравнивать → Движки»** и одну БД. Для сравнения баз выберите **«Базы данных»** и один движок. Результаты разных языков не объединяются в одну медиану. Неуспешные/отсутствующие результаты остаются видимыми.

При заданной частоте скорости могут быть близки к одной цели: такой тест проверяет способность выдержать поток. Сравнивайте p99, ошибки и пропуски, а не делайте вывод о предельной скорости по небольшой разнице около целевой частоты.

Это сравнение **реализаций клиента: язык + runtime + драйвер + модель параллельности**. У Python есть GIL, у Node.js выделены рабочие потоки, у Java виртуальные потоки, у Go goroutine; SQLite тоже использует разные сборки библиотеки. Серверная подготовка запросов зависит от драйвера: PyMySQL использует параметризацию на клиенте, JDBC/pg/mysql2 и другие драйверы имеют собственную подготовку и кеши. Одно число не доказывает превосходство языка.

Данные, запросы, гарантии записи, размер пакета, классификация успешных операций, контроль количества/сумм и алгоритм гистограмм согласованы. Для PostgreSQL все реализации используют binary COPY, для MySQL/MariaDB — multi-row INSERT, для MongoDB — insertMany, Redis/Valkey — pipeline HSET, SQLite — транзакцию, ClickHouse — HTTP JSONEachRow.

CPU и RSS относятся к отдельному процессу движка, включая его рабочие потоки. GC/выделения памяти сохраняются только при наличии измерения: C# — метрики .NET, Go — счётчики runtime, у остальных поля пустые. Нулём отсутствие измерения не заменяется. Короткие функциональные проверки подтверждают работу, их скорости нельзя использовать как рейтинг языков.
